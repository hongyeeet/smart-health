### 2. Google Cloud Vision OCR experiment
- Script: `services/api/scripts/vision_ocr_experiment.py`. It is **not used by the app**. It reads the same photos with Cloud Vision (DOCUMENT_TEXT_DETECTION) and with the local reader the scanner uses now (RapidOCR, `app/services/scan_privacy.py`) and compares time, lines, confidence, expected words found, and which lines the app's masking would have hidden but Vision had already seen.
- **No credentials are stored anywhere**, by Hong Yi's choice. Joely runs it with her own Google Cloud account:
  1. `gcloud auth application-default login`
  2. Enable the Cloud Vision API on her project (console: APIs and Services, Library, Cloud Vision API).
  3. `cd services/api` then `python scripts/vision_ocr_experiment.py --synthetic --project <her-project-id> --out ../../docs/review/vision-ocr`
- Vision refuses API keys, so `GOOGLE_API_KEY` will not work. The app's project `smart-health-510414` was not reachable from Hong Yi's account.
- This machine had an old Google sign-in that pointed at a deleted project (`great-system-esg-cgsi`), so a first run on 2026-10-14 sent the made-up labels to Google and was rejected. If a sign-in like that is on Joely's machine, pass `--project` or run `gcloud auth application-default revoke`.
- **Privacy rule (D-063):** Vision needs the original photo, with the patient's name and NRIC. The scanner blacks those out before anything leaves the machine. The script only reads the made-up labels in `tests/fixtures/make_label_images.py` unless `--allow-real-photos` is passed. Do not use real patient labels. If Vision wins, using it for real would be a decision to take with Hong Yi, because it changes that rule.
- Baseline from the local reader alone (2026-10-14, six made-up labels): 19 of 20 expected words found, about 1.8 s per photo. It found no text on the heavily blurred label.
